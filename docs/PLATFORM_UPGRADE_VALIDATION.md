# 全站回归与部署演练 · 2026-10-16

本轮检查功能、账号隔离、异常操作、真实数据库、浏览器、备份恢复和并发容量。测试按场景组合覆盖，不等于穷举所有输入，也不能证明任何环境下都没有问题。这里记录实际执行结果，未执行的部分单独列出。

## 本轮新增

- 代码可视化：C / Python / Java / JavaScript 算法子集、变量与数组图、逐步回放、调用栈、事件计数、私有历史与 JSON / SVG 导出。
- 群组：查看自己发出的邀请与申请、状态分页、撤回待处理记录。
- 站内信：个人归档、回收站、恢复、批量已读和批量整理；不影响其他参与者。
- 素材：空间统计、引用检查、回收站、完整文件名确认永久删除；清理失败重试。
- 搜索：MySQL 全文索引与原有权限范围组合，编辑后立即更新。
- 运行：跨实例通知、任务领取租约、确认与到期重交付、启动阶段分析、可选长期监控。
- 部署：训练按需启动、基础服务与上传依赖分开就绪、在线加密快照、独立环境恢复、数据库日志重放、API 版本切换和回退。

恢复演练最后一轮约 173 秒，包含生成快照、新建独立环境、校验附件、日志重放和清理；这不是网站日常启动时间。演练临时项目、数据卷、合成标记及临时备份均已清理。

本轮修复了几个实测问题：MySQL 初始化阶段的健康误判、附件流式上传兼容性、恢复镜像缺少日志解析工具，以及对象删除失败被忽略。SQL 快照改为读取头部坐标、流式导入，避免整份数据库导出进入内存。

并发诊断还定位到两个查询瓶颈：词汇首页对整套词库反复做进度聚合，以及少量个人笔记使用全站词项索引。词汇统计拆分为词数统计和当前用户进度关联，增加按词项查询的索引；个人笔记不超过 1,000 篇时优先按所有者索引检索，较大集合再使用全文索引。查询路径变化不改变账号隔离，词汇的跨书进度、Skip 和私有词书统计继续回归。

## 性能记录

100 个独立账号、初始 10,000 篇笔记，按 10 / 50 / 100 用户并发执行七类混合操作，各重复三轮。共 3,360 次正常请求通过，480 次跨账号读取被拒绝。测试仅关闭容量阶段的频率限制，保留认证与所有权检查。

| 并发用户 | 优化前 P95 | 优化后 P95 | 优化后 P50 |
| --- | ---: | ---: | ---: |
| 10 | 1430 ms | 743 ms | 261 ms |
| 50 | 3327 ms | 2966 ms | 1285 ms |
| 100 | 4874 ms | 3623 ms | 1667 ms |

这是 Windows Java 进程通过本机 HTTP 访问 Docker MySQL 的结果；不包含浏览器渲染、公网延迟或外部 AI。100 并发 P95 下降约 26%，但仍为秒级，不作为大规模公网容量承诺。SQL 诊断输出包含归一化语句和耗时，不记录用户查询值。

### 日常启动实测

Docker 引擎已运行，停止后启动现有八个默认服务，不构建、不下载、不重新创建容器：页面业务 API 在 **47.71 秒**可用，核心服务健康检查和全部默认服务在 **50.27 秒**通过。代码解释服务在 8.89 秒、病毒扫描在 45.62 秒就绪。可选训练和监控在此测试中保持运行。

后端自身启动约 44 秒，仍是这台电脑冷启动的主要耗时；没有把静态页面出现的时间当作网站可以正常使用。这个结果不包含 Docker Desktop 启动、首次安装和镜像构建，也不是接口响应延迟。

服务已经运行时，再执行日常启动脚本共 **2.33 秒**，确认健康后直接打开原服务，不再重复重启或构建。

## 尚未覆盖的环境

- 代码执行是明确限制语法的教学解释器；不支持任意工程、指针、实例对象或系统接口，不把估算冒充完整编译器分析。
- 没有调用真实付费 AI、发送真实短信或邮件，也没有实测外部供应商计费、延迟和配额。
- 没有部署到公网、跨机房或多台物理服务器；本机容量数据不能直接当作云端容量承诺。
- 数据库日志重放不包含快照之后新增的附件；训练模型检查点需要完整备份。
- 监控目前提供本机看板和规则告警，外部通知渠道需要部署者配置。
- 邀请记录保留每个群组与对象的最新状态；永久擦除共享群历史和共享邮件不是本轮提供的操作。
